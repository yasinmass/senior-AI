### What Must Change

1. **LLM**: Groq API → **Qwen2.5 via Ollama** (local)
2. **TTS**: gTTS (cloud) → **Piper TTS** (local)
3. **Emotion**: pysentimiento (English-only) → **XLM-Roberta** (multilingual)
4. **Memory**: Raw ChatHistory → **ChromaDB** (semantic vector memory)
5. **VAD**: None → **Silero VAD** (voice activity detection)
6. **Embeddings**: None → **all-MiniLM-L6-v2** (for ChromaDB)

## User Review Required

> [!IMPORTANT]
> **Ollama Must Be Pre-Installed**: This plan assumes Ollama is installed on the deployment machine and `qwen2.5:7b` model is pulled. The code will include setup instructions but cannot auto-install Ollama itself.

> [!IMPORTANT]
> **Piper TTS Binary Required**: Piper TTS requires downloading pre-built voice model files (~30-80MB each) for each language. Setup instructions will be provided. Tamil voice availability may be limited — fallback to English Piper voice + LibreTranslate will be implemented.

> [!WARNING]
> **Breaking Change**: The Groq API key will no longer be required for the companion chat. The `GROQ_API_KEY` setting and frontend API key input will be removed from the Bhavi flow. Other features that may use Groq are not affected.

---

## Open Questions

> [!IMPORTANT]
> **Piper TTS Tamil Voice**: Piper has limited Tamil voice models. Should we use English Piper + transliteration for Tamil, or keep gTTS as a Tamil-only fallback? **Plan**: Use Piper for English, keep gTTS as optional fallback for Tamil/Hindi while Piper voices catch up.

> [!NOTE]
> **Qwen2.5 Model Size**: The plan uses `qwen2.5:7b` for balance of quality + speed on consumer hardware. If the deployment machine has <8GB RAM, we can switch to `qwen2.5:3b`. Which size do you prefer?

## Proposed Changes

### New Backend Service Layer — `backend/core/bhavi/`

All Bhavi AI services will be modularized into a new `bhavi/` package under `backend/core/`. This replaces the monolithic inline code in views.py.

#### [NEW] `bhavi/__init__.py`
Package init — exports all service interfaces.

#### [NEW] `bhavi/config.py`
Central configuration for all Bhavi services:
- Ollama model name & endpoint
- Whisper model size
- ChromaDB collection names
- Piper TTS voice paths
- Emotion model identifiers
- VAD thresholds

#### [NEW] `bhavi/stt_service.py`
**Faster-Whisper STT Service** — refactored from inline views.py code:
- Lazy model loading (singleton pattern)
- Automatic language detection (Tamil/Hindi/English)
- Configurable model size (`small` → `medium` upgrade path)
- Microphone streaming support via WebSocket-ready interface
- Audio format conversion (webm → wav)
- Silero VAD integration for start/stop detection

#### [NEW] `bhavi/llm_service.py`
**Qwen2.5 via Ollama LLM Service**:
- Ollama HTTP API integration (`http://localhost:11434/api/chat`)
- Streaming response generation (yields chunks)
- Empathetic system prompt crafted for elderly care
- Context window management (session memory + retrieved memories)
- Graceful fallback if Ollama is unavailable
- Personality: gentle, warm, non-robotic, calm companionship

#### [NEW] `bhavi/emotion_service.py`
**XLM-Roberta Multilingual Emotion Detection**:
- Primary model: `cardiffnlp/twitter-xlm-roberta-base-sentiment-multilingual`
- Advanced layer: `monologg/bert-base-multilingual-cased-goemotions-ekman` (GoEmotions)
- Detects: sadness, loneliness, stress, anger, joy, neutral
- Emotional trend tracking (rolling window)
- Risk indicator generation (crisis scoring)
- Works for Tamil, Hindi, and English natively

#### [NEW] `bhavi/memory_service.py`
**ChromaDB Semantic Memory System**:
- Local persistent ChromaDB instance
- Embedding model: `all-MiniLM-L6-v2` via sentence-transformers
- **Short-term memory**: Recent 10-turn session context
- **Long-term memory**: 
  - Emotional summaries (daily/weekly)
  - Important personal references (family, events)
  - Language preference
  - Recurring emotional patterns
- Summary-based storage (not raw conversations)
- Semantic similarity retrieval for contextual responses
- Privacy: no raw audio stored, summaries only

#### [NEW] `bhavi/tts_service.py`
**Piper TTS Service**:
- Local Piper TTS binary integration
- Streaming voice output (WAV chunks)
- Elderly-friendly speaking pace (rate adjustment)
- Calm conversational tone
- Language-specific voice model loading
- Fallback chain: Piper → gTTS → silent

#### [NEW] `bhavi/vad_service.py`
**Silero VAD Service**:
- Voice Activity Detection for start/stop speaking
- Reduces unnecessary processing
- Integrates with STT pipeline
- Configurable silence thresholds

#### [NEW] `bhavi/pipeline.py`
**Main Bhavi Pipeline Orchestrator**:
```
User Speech → VAD → Faster-Whisper STT → Emotion Detection
    → Memory Retrieval (ChromaDB) → Qwen2.5 Response → Piper TTS → Voice
```
- Orchestrates the full pipeline
- Handles streaming (begin TTS while LLM still generating)
- Latency optimization: parallel emotion detection + memory retrieval
- Error handling & graceful degradation
